    Replay S0c — JUnit export from result files (plan)¶

    Issue #274 · PRD #271 (slice S0c, ungated) · branch replay/274-junit-export · version 0.38.1

    Goal¶

    mauto result export --run-id <id> [--run-id <id>…] --format junit [--out <path>] turns finalized result files in .mobile-automator/results/ into one JUnit XML document a CI test reporter can ingest. The renderer lives in src/run/report/ so R6's mauto run --junit reuses it unchanged.

    File structure¶

    File Change

    src/run/report/index.js new — REPORT_FORMATS (['junit']) and renderReport(format, results, opts); the one entry point cli.js (and later run) calls
    src/cli.js handleResultExport + the result export subcommand (wrapped in requireWorkspace), exported for unit tests

    Module interfaces¶

    // src/run/report/junit.js
toJUnit(results, { executor } = {}) -> { xml, suites, tests, failures, skipped }
    • <testsuites name="mauto" tests failures skipped errors="0" time> wrapping one <testsuite> per result, in input order (name = scenario_id, timestamp = metadata.timestamp, time = duration_seconds).
    • <properties>: run_id, status, the five metadata fields, and executor.<key> for every scalar key of result.executor ?? opts.executor — emitted only when present (R2 adds root executor; R6 passes it in).
    • One <testcase> per assertion_results[] entry (name = assertion_id, classname = scenario_id): passed → empty, failed → <failure message type> with expected / actual in the body, needs_agent → <skipped message>. Optional R2 fields (type, step_id, judge) are used when present (failure type, name prefix), ignored otherwise.
    • One <testcase name="step: <step_id>"> per step whose status is failed or error (<failure type="step_failed|step_error"> with error_message), and per step with needs_agent: true (<skipped>). Passed/skipped steps emit nothing.
    • Guard against a green report for a red run: when status is failed/error and no failing testcase was produced, one synthetic <testcase name="run status"> failure is added saying so.
    • XML 1.0 escaping of & < > " ' in text and attributes; characters illegal in XML 1.0 (C0 controls except tab/LF/CR, lone surrogates) are stripped. Deterministic output (no clock reads) so fixtures compare exactly.
    // src/run/report/index.js
REPORT_FORMATS            // ['junit']
renderReport(format, results, opts) -> { format, content, suites, tests, failures, skipped }
// throws a TypeError naming REPORT_FORMATS on an unknown format

    // src/cli.js
handleResultExport({ projectRoot, cwd, fsDep = fs }, { runIds, format, out })
  -> { envelope, exitKind }
    • --run-id repeatable (collect), at least one; each must match the result schema's ^run_\d{8}_\d{6}$ — this also forbids path traversal through the id.
    • Reads <workspace>/results/<id>.json directly with fs.readFileSync, not through ResultStore: the store's constructor renames a corrupt file aside, and a read-only verb must never mutate the workspace.
    • invalid_input for: unknown/missing format (hint lists formats), bad id, missing file, unparseable JSON, and a not-yet-finalized file (_in_progress: true; hint: run mauto result finalize --run-id <id> first). One failing id fails the whole export (no partial XML).
    • --out resolved against cwd, parent dir created, written atomically (src/util/atomic.js); write failure → environment (same as crash get --out).
    • Success: ok({ format, path, suites, tests, failures, skipped }); path is the absolute out path or null, and without --out the XML is in data.xml.
    • Always exit 0 when the export itself succeeded, whatever the test outcome — export is a report, not a gate (S0b owns test-failure exit codes). Documented in cli-verbs.md.

    Guards touched¶

    • tests/lint/result-coverage.test.js — the no-orphan-flags rule would flag export --format / --out. Add, in the test, a declared map READ_ONLY_RESULT_VERBS = { export: '<reason: reads finalized result files and renders a report; writes no result-file fact, so it has no capability to claim>' }, skip only those subcommands in the orphan scan, and add three tests that keep the exemption honest: every entry has a non-empty reason and names a registered result subcommand; no exempt verb is the verb of any RESULT_CAPABILITIES entry (a writer cannot hide behind the exemption); and, behaviourally, running handleResultExport against a temp workspace leaves the results/ directory byte-for-byte unchanged.
    • workspace-dirname-single-source — new src/ code builds paths only from workspaceDir(); no .mobile-automator literal.
    • vocab VERB_NAMES — records the top-level command (result), already present: no change.
    • ESLint type-aware rules — new code is synchronous; nothing to observe.
    • Version-bump gate, lockfile-in-sync — 0.38.1 in both files.

    Tests (written first)¶

    1. junit.test.js: well-formed XML for every fixture; root/suite counts; passed assertion has no child; failed assertion → <failure> with message, expected, actual; failed step → testcase + <failure type="step_failed">; errored step → step_error; needs_agent assertion → <skipped> and counted in skipped, not failures; incomplete result suite carries status=incomplete property; executor properties from result.executor and from opts.executor, and none when absent; synthetic "run status" failure for a failed result with no failing entries, and none for a passed one; escaping of & < > " ' and stripping of control chars; multiple results → multiple suites in order; output identical across two calls.
    2. index.test.js: REPORT_FORMATS is ['junit']; renderReport('junit', …) equals toJUnit's output; unknown format throws naming the formats.
    3. result-export.test.js: happy path with and without --out; two run ids → two suites; each invalid_input case above; --out into a missing directory creates it; corrupt file left untouched (no .corrupt.* sidecar).
    4. cli-smoke.test.js: write a result file into a temp workspace, spawn result export --run-id … --format junit, envelope ok, exit 0, data.xml parses and names the scenario; second case with --out writes a parseable file; a bad format exits with the invalid_input code through the envelope.
    5. result-coverage.test.js: the three exemption tests above.

    Docs¶

    • docs/reference/cli-verbs.md: row mauto result export --run-id <id> [--run-id …] --format junit [--out <path>] and a note: mapping (suite per run, case per assertion and failed step, needs_agent → skipped, provenance as properties), finalized files only, exit 0 regardless of test outcome.
